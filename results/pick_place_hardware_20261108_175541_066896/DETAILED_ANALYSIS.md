# 2026-11-08 准备动作中断：详细原因分析

本轮只执行了原基线的张爪和部分pregrasp准备运动，完整OSCBF尚未开始。执行代码版本为 `40eb3b871df2d028fe154ab396c6932628ab5e04`。分析依据为原始CAN、SDK发送调用、控制/反馈记录、异常快照和单独复位记录；没有新增实机动作或图形展示。

## 1. 直接触发原因

不是接收线程真的停了2.39秒：CLOCK_REALTIME相对CLOCK_MONOTONIC向前跳变约2.390776秒。原代码同时检查单调接收年龄和日历时间年龄；后者一项就使OR条件成立。两个epoch时间戳原本属于同一可校正时钟，错误在于把可跳变的差值当作流逝时间。

| 项目 | 记录值 |
|---|---:|
| 实时时钟相对单调时钟的跳变 | 2.390776 s |
| 异常时日历时间表达式给出的帧年龄 | 2394.108 ms |
| 同一完整反馈的单调回调年龄 | 3.137 ms |
| 跳变前后两组六轴反馈的回调间隔 | 4.738 ms |
| 全程最大完整反馈回调间隔 | 30.346 ms |
| 原有超时值 | 200 ms |
| CAN错误帧 / SDK发送异常 | 0 / 0 |

最新反馈序号4832→4833仍连续。控制器和六轴驱动的独立原始接收也连续；它们的旧epoch年龄同样会被这次时间跳变抬高。因此只改一个关节判断而保留控制器/驱动/夹爪的旧比较仍会留下同类问题。

另有一次约29.8ms的SDK发送调用延迟，发生在此次异常前约7.42秒。它小于200ms，也不在本次触发时刻，不能与实时时钟跳变合并解释。

## 2. 为什么从软件异常变成电子急停

旧异常处理先再次执行 `device.state(enabled=False)`，准备确认状态后进入零速停止。该调用重复了同一个错误的时间比较，`stop_state_error` 再次记录 `Fresh complete joint feedback interrupted`，于是进入电子急停分支。

| 相对异常时刻 | 事件 |
|---:|---|
| -3.137 ms | 最新完整反馈已到达 |
| 0.000 ms | 抛出反馈中断异常 |
| 0.654 ms | 开始发送六轴零速度 |
| 0.775 ms | 发送0x150，载荷0100000000000000 |
| 46.911 ms | 状态快照已显示arm_status=1 |
| 3003.352 ms | 停止后只读状态快照 |

异常后的发送记录只有6帧零速度请求和1帧电子急停。该段没有回零位置目标，也没有reset。零速度请求与关节零位目标是不同命令。

## 3. 急停后的姿态变化

厂家SDK明确写明：电子急停时，抬起的关节会以阻尼方式缓慢落下；它不等于固定位置保持。[厂家急停说明](https://github.com/agilexrobotics/pyAgxArm/blob/d90e234ba8e408cfa964b38aa9120b3131fc9f85/docs/piper/piper_api.md#L4402)。因此使能位仍真不能证明手臂被锁在原姿态。

| 记录时刻 | J2反馈 | J5反馈 |
|---|---:|---:|
| 触发异常时 | 76.680° | 60.113° |
| 急停后约3秒 | 99.361° | 61.877° |
| 17:56:52只读记录 | 133.561° | 90.364° |
| 18:28复位前 | 133.561° | 90.364° |
| 18:28复位后 | 133.594° | 90.373° |

这些是编码器/控制器反馈，不是外部计量。变化发生在电子急停之后、后续reset之前，与厂家描述相符；日志不能排除人工扶持调整等贡献，不能进一步宣称全部位移已由某一种物理机制单独解释。

## 4. 18:28的复位是另一个独立动作

用户确认停稳并支撑后，执行了已有的 `recover_task_hold.py --reset-only --execute`。结果为reset_only_completed，reset_sent=true、enable_sent=false、motion_sent=false，最终arm_status=0、六轴enabled=false。没有使能、回零或续跑。
[厂家reset说明](https://github.com/agilexrobotics/pyAgxArm/blob/d90e234ba8e408cfa964b38aa9120b3131fc9f85/docs/piper/piper_api.md#L4426)定义了立即失电；当前应保持支撑，不能把失能状态当作机器人自行保持位置。

## 5. 已做的代码清理

- 当前主执行链、只读状态和单独复位入口改用单调接收时刻计龄；原始epoch时间戳仍归档，原有时限未扩大。
- 清理了cpv_axes_demo、cpv_j6_demo、return_to_zero、audit_controller_limits、home_zero_simple里的同类epoch时间比较。
- 删除软件异常零速停止前的重复state判据。先立即发送零速度，再按原10ms节拍发送后续零速，不重复用同一个失败条件拦住停止请求。
- 显式Ctrl+C/急停功能与原有真实发送失败处理保留；没有自动reset或重新使能。
- 此前新增的夹爪漂移、稳定性、预检/哈希、额外阈值及测试入口仍已删除；本轮没有加新测试或拦截来替代。
