# 完整任务参考与阶段推进的离线检查

模块：`piper_oscbf/task_reference.py`。检查入口：

```bash
env -u LD_LIBRARY_PATH ./envs/oscbf/bin/python -I scripts/check_task_reference.py
```

这组检查不导入 SDK、不连接 CAN、不实例化机械臂几何、不生成图片。它验证参考管理逻辑，不是完整过滤器、碰撞约束或实机任务通过的证据。历史无过滤器执行器继续使用原策略；本模块供共同的 CBF／OSCBF 执行链使用。

## 接口

```python
reference = StageReference(saved_arm_step, effective_stage_velocity_cap)
governor = PhaseGovernor(reference, arrival_tolerance_rad=cfg["arrival_tolerance_rad"])
phase = governor.update(q_measured, now=time.monotonic())
q_ref, qd_ref = reference.sample(phase.phase_s)
qd_ref = qd_ref * phase.rate
record = phase.as_dict()
# 阶段切换只能在 phase.done 为真时进行。
```

`PhaseState.rate` 是经过时间步长和路径边界限制后的实际参考相位速率；`requested_rate` 是策略提出的速率，`actual_phase_rate` 记录相位差除以实际时间差。第一次观测没有已过去的时间区间，`rate` 使用初始策略值。最后参考点前馈速度恒为零，实际状态未到位时仍等待当前名义控制器消除末端误差。

## 推进规则

- 保留所有原规划点和原 `path_arrays()` 的速度重定时：分段时间取原时间、半速度上限所需时间与 10 ms 三者的最大值。
- 内部参考点使用右侧线段导数；最终参考时刻前馈为零。单点参考和相同位置的定时保持都有明确目标，不会跳过实际到位要求。
- 参考速度只由当前线段切向滞后降低，不使用全关节误差范数直接冻结相位。当前切向定义在关节路径空间；不宣称任意 TCP 横向位移也必然在这个度量中横向。
- 默认最大切向滞后参数为 0.20 参考秒；相位速率在 0–1 范围，极小速率变为明确暂停。每次相位最多推进 0.05 s，而且到下一个保存点必须先停在该参考边界，不会因调度迟到而连续跳过多个路径转折点。
- 实际测量没有有效进展达到 5 s，或者阶段时间达到 `4 × reference_duration + 10 s`，抛出 `ReferenceBlockedError`，携带最后阶段状态及停止原因。执行器应保留该受阻结果并调用既有停止处理，不自动复位或重试。
- 阶段完成要求参考到达末端，并且实际六轴最大绝对误差不超过传入的原到位阈值；没有放宽到位容差。
- 已到位的定时静止保持不因缺少预期外的运动而触发“无进展”。未到位的保持仍受有限超时约束。

3. 实际状态完全受阻时，在测试设定的 0.5 s 无进展期限触发有限停止；没有用参考时钟推进伪装实际完成。

## 记录与公平对照

`checks.json` 保存检查结果和默认参数。`transverse_phase_trace.json` 保存横向修正测试的相位、速率、误差、暂停与到位状态；`observed_schedule.json` 是明确标记为 `observed_trace_not_yet_replayed` 的实际相位记录。

`make_schedule_record()` 保存精确参考签名、实际 elapsed/phase 序列和日程 SHA-256，为将来共同日程回放提供可识别数据。这里没有实现固定日程执行器，也没有把自适应运行宣称为严格同时间对照。完整任务自适应比较应同时报告耗时并按实际相位对齐；将来回放须核对参考签名并实际使用相同日程。
